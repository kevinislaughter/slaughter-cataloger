The Suite

Slaughter Cataloger is a suite of local-first browser tools for documenting serial publications — newsletters, magazines, journals, newspapers, zines, bulletins, and any other publication issued in numbered installments.

Everything runs locally in your browser. No account, no server, no data leaves your machine. Each tool is a single HTML file; the suite is a folder. Output is standard CSV — readable by every data tool that has ever existed and every one that will. As AI-assisted conversion becomes routine, a well-structured CSV can be transformed into virtually any target format with minimal effort. The data you enter today is not hostage to any particular piece of software, including this one.

The suite consists of four tools:

Titles — manages title-level metadata: the publication's canonical title, publication history, publisher, editors, frequency, ISSN, city, country, and extended notes (mission statement, editorial statement, bibliographic notes). Creates the TitleID, which is the upstream key for the entire suite. → Open Titles

Issues — the canonical issue list. Records what was published, when, and under what numbering: volume, issue number, whole number, year, month(s), day, date as printed, contributors, edition, printer, printer location, issue designation, price, pages, size, short name, and notes. Requires a Titles CSV. → Open Issues

Contents — records what appears inside each issue: articles, poems, editorials, correspondence, advertisements, authors, page ranges, content types, and notes. Each contents entry links to its parent issue via IssueID. Requires an Issues CSV. → Open Contents

Compiler — produces formatted outputs from your data. Loads the CSVs required for the selected output type: Checklist (Issues only), RIS for Zotero (Titles + Issues + Contents), Proofing Catalog (Titles + Issues + Contents, print-optimised for physical verification), and WordPress Catalog (native Gutenberg block markup). → Open Compiler

Workflow

The suite follows a locked dependency chain. Each tool depends on its upstream data and will not accept records until the appropriate CSV is loaded:

Titles (no dependencies) → export Titles CSV → Issues (load Titles CSV, select a title) → export Issues CSV → Contents (load Issues CSV, select an issue) → export Contents CSV → Compiler (load Titles CSV, select a title, load the required source CSVs, then generate output)

This prevents orphaned records and ensures the suite's data hierarchy is always consistent. Each tool validates loaded files by checking the Slaughter Cataloger Tool column in every CSV row. Loading a Contents CSV into the Issues tool, for example, is rejected with an error.

The Title Library Slug — a machine-friendly identifier for your themed collection (e.g. EXAMPLE-LIBRARY) — is set in the Titles app and carried through every CSV in the chain. The Compiler validates that loaded files share the same slug.

Titles — What It Tracks

The Titles app manages publication-level metadata — facts about the journal as a whole, not about individual issues. Fields are organized into four tiers:

Title Library — Title Library Slug (required, machine-friendly), Title Library Name, Title Library Note. These define the themed collection and are sticky across all records.

Title Identity — Canonical Title, Title Code (8 characters, auto-suggested), First Year of Publication (CE), First Year Note, Original/First Published Title, Subtitle. TitleID is computed from Title Code + First Year.

Title History — Former Title(s), Later Title(s), Related Title(s).

Publication Details — Publisher, Editor(s), City, State/Province, Country, Language, Frequency, ISSN.

Extended Notes — Publication History Note, Mission Statement/Prospectus, Introduction/Editorial Statement, Bibliographic Note, General Notes.

Issues — What It Tracks

The Issues app produces a canonical issue list: a record of what was published, when, and under what numbering. It is not a holdings inventory — it does not track which copies you own. It answers the prior question: what issues exist?

Issues are organized into two form tiers, with identification computed at the bottom:

Title Level — inherited from the selected Title, editable per-issue: title, subtitle, former/later titles, publisher, editor(s), ISSN, language, series, series number, city, state/province, country, frequency.

Issue Level — volume, issue/no. within volume, whole number, year (CE/Alt. calendar), month(s)/season, day, date as printed, contributors, edition, printer, printer location, issue designation (via Special toggle), supplement label, price, pages, size, short name, and notes on issue. Examined/Reported toggle with evidence note.

Identification — TitleID (inherited from selected Title), IssueID (generated on first Record, permanent). Both displayed read-only.

Auto-advance, season mode, duplicate detection, and the full field-state system are described under Key Features below.

Contents — What It Tracks

The Contents app records what appears inside each issue — essentially a table of contents that can be as detailed as the compiler wants. Each entry links to its parent issue via IssueID.

Fields per entry: sequence (auto-advancing per issue), item title, author/credit, content type (article, poem, editorial, correspondence, advertisement, etc. — free text with a datalist of common values), parent item (for nested items like poems under a section heading), start page, end page, and notes.

Contents uses the same field-state system as Issues. A field may be filled normally, marked speculative with ?, marked N/A, or left unaddressed. This is especially useful for uncredited items (Author = N/A), uncertain page ranges (Start Page = ?), supplied titles (Item Title = ? with bracketed text), and top-level items (Parent Item = N/A).

Item Title is required — it cannot be marked N/A. If no printed title exists, enter a supplied title in brackets and mark it speculative.

Compiler

The Compiler produces formatted, human-readable outputs from your data. It does not store records — it reads CSVs and generates documents.

Current output type: Checklist — a per-issue list in one of three styles:

Plain — ☐ Vol. 1, No. 1 — May 1872 — quick reference.

Bibliographic — full citation line with optional publisher, printer, pages, size, price.

Technical — IssueID-led: EXAGAZEX-1872-K7M4Q2 — Vol. 1, No. 1 — May 1872

Twelve toggleable options: checkboxes, IssueID, page count, physical size, price, publisher, printer, speculative flags, notes, subtitle, issue designation, evidence basis. Options auto-regenerate the preview.

Four export formats: Copy (plain text to clipboard), HTML (standalone page), Markdown (with task-list checkboxes), Plain text file.

Export filenames follow the convention SCATOUT_SLUG_TITLEID_TYPE_DATE.ext when output covers one title, or SCATOUT_SLUG_TYPE_DATE.ext for library-wide output:

ScopeExample
Checklist, single titleSCATOUT_EXAMPLE-LIBRARY_GAZETTEX-1895_CHECKLIST_20260714.html
RIS, single titleSCATOUT_EXAMPLE-LIBRARY_GAZETTEX-1895_RIS-ZOTERO_20260714.ris
RIS, library-wideSCATOUT_EXAMPLE-LIBRARY_RIS-ZOTERO_20260714.ris
Proofing CatalogSCATOUT_EXAMPLE-LIBRARY_GAZETTEX-1895_PROOFING-CATALOG_20260714.html
WordPress CatalogSCATOUT_EXAMPLE-LIBRARY_GAZETTEX-1895_CATALOG-WPBLOCKS_20260714.txt

RIS for Zotero. Exports each Contents item as one RIS record, enriched with issue and title metadata from the full CSV hierarchy. Requires all three upstream CSVs (Titles + Issues + Contents). Maps to standard RIS fields: TI (item title), AU (author), T2 (journal title), PY/DA (date), VL/IS (volume/issue), SP/EP (pages), SN (ISSN), LA (language). Slaughter Cataloger identifiers (TitleID, IssueID, Title Library Slug) are preserved in KW and N1 fields. Semicolon-separated authors export as multiple AU lines. Speculative and N/A states are noted in N1. Export filename: SCATOUT_SLUG_RIS-ZOTERO_DATE.ris.

Future output types — bibliography and contents listing — are listed in the format dropdown but not yet active.

Filename Policy

Working CSV files use stable, undated filenames. Schema version and date do not appear in working filenames — the schema version is stored inside each CSV row (Schema Version column). Apps validate schema from CSV contents, not from filenames.

Compiler outputs are generated snapshots and are date-stamped by default.

Example filenames:

Titles CSVSCAT_EXAMPLE-LIBRARY_TITLES.csv
Issues CSVSCAT_EXAMPLE-LIBRARY_GAZETTEX-1895_ISSUES.csv

IssueID

IssueID is the permanent master key used across the Slaughter Cataloger suite. It connects records between Titles, Issues, Contents, Compiler, and any future related tools. It is not a citation, display label, issue number, or sort order. It exists so that every tool can refer to the same issue without relying on editable text such as Short Name.

The format is: TITLECOD-FIRSTYEAR-KXXXXXX

Example: EXAGAZEX-1872-K7M4Q2

TITLECOD (8 characters) identifies the title or run — auto-suggested from the canonical title in the Titles app, editable. FIRSTYEAR (4 characters) records the first known publication year of the title, using X for unknown digits (e.g. 189X, XXXX). Together these form the TitleID (EXAGAZEX-1872). KXXXXXX is a generated non-sequential token using a safe alphabet (no I, O, 0, 1, L, X) that makes each issue unique without implying order.

IssueID is generated when a new issue is first recorded and never changes unless deliberately migrated. Editing a title, renaming a Short Name, reordering rows, or adding newly discovered issues does not affect existing IssueIDs.

Field States

Every field in the Titles, Issues, and Contents apps can be in one of four states, and the interface makes all four visually distinct:

Filled — normal confidence. You've entered a value and stand behind it. The text appears in bold dark orange, distinct from labels and placeholder text.

Speculative. You've entered a value, but something is uncertain — the masthead is missing, the date was illegible, the information is secondhand, or what's printed is known to be wrong. Check the ? beside the field. The entry-wide Speculative toggle lights up automatically when any field is marked ?; it turns off again when all field-level ? marks are cleared. If you click the Speculative header toggle manually, that choice is preserved until the next Record. N/A and Speculative are mutually exclusive per field — activating one clears the other.

N/A. This field simply doesn't apply — the publication has no volume numbering, or ISSN was never assigned, or the contents item has no credited author. Clicking N/A grays the field out, displays [N/A] as placeholder text, and records it as explicitly addressed. This is meaningfully different from leaving a field blank: it says I considered this and it isn't applicable, not I haven't gotten to this yet.

Unaddressed. The field has not been touched — no value, no ?, no N/A. These fields show a light orange underline. This is a prompt, not an error. When you hit Record with unaddressed fields, a prompt lists them and asks whether to proceed or go back. After recording, any fields that cleared will show the orange underline again as a gentle nudge.

Hover over any field label for a tooltip explaining what belongs there and how it differs from adjacent fields.

A Note on Scope

This suite is designed for the full range of serial publishing — from mainstream magazines and newspapers to academic journals, trade publications, literary reviews, newsletters, and small-press periodicals with irregular publication history and idiosyncratic numbering. Fields like Former Title(s), Later Title(s), Alt. calendar, Supplement, and Issue Designation are not afterthoughts — they are there because the material demands them.

The Cataloger does not tell you how to catalog. It gives you a structure flexible enough to meet the material on its own terms.

Release History

Beta 2.6  —  July 2026

New Compiler output modes. WordPress Catalog exports native Gutenberg block markup (headings, paragraphs, tables, separators) that pastes directly into the WordPress Code Editor as fully editable blocks. Proofing Catalog generates a print-optimised verification document — one issue per printed page, with checkboxes, correction columns, and reviewer signoff blocks for every field at title, issue, and contents level. Full Catalog HTML produces a standalone downloadable page with embedded CSS.

Catalog structure. Issues are grouped into volume or year subheadings when a catalog contains more than ten issues, giving ToC plugins a two-level navigation structure. A Scope panel lets you filter which volumes or year groups appear in any output — load a 403-issue run, select Volume 1, and every output type covers only those 26 issues. Outputs only show title-level metadata for titles that actually have issues loaded; loading a library-wide Titles CSV no longer produces ghost title blocks for unloaded journals.

Compiler reliability fixes. Unified updateOutputReadiness() function called after every CSV import. Full RIS cross-validation: slug matching across all three CSVs, orphan IssueID detection, TitleID chain verification, blank key rejection. Escape helpers are string-safe. Titles CSV parsed as a full library manifest. Context-sensitive options panel hides irrelevant controls per output type. Export RIS button hidden unless RIS format is active. Output-format selector excluded from auto-regenerate listener.
